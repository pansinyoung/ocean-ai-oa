# Acceptance Scenarios (A1–A7)

Each scenario states the trigger, the expected outcome, the implementation points that guarantee it, and how to verify it. `npm run verify` automates these where feasible; README.md documents the manual reproduction too.

| ID | Given | Expected | Implementation guarantee | Verify |
| --- | --- | --- | --- | --- |
| A1. Tenant isolation | Bob (West) hits list/detail/bulk-issue/export for East data. | Only West data visible; cross-tenant detail → 404/non-revealing; cross-tenant bulk-issue rejected with zero certs and zero audit rows. | Every query scoped by actor-derived `tenant_id`. Detail/revoke 404 on mismatch. Bulk-issue rejects before any write. | `verify`: Bob → list East course/cert returns empty/404; bulk-issue East course → 4xx and row counts unchanged. |
| A2. Retry safety | Alice sends the same bulk request with the same key, sequentially and concurrently. | One logical op; each eligible learner gets at most one cert; one audit event per issuance; all callers see the same outcome. | Idempotency table unique `(tenant_id, key)` + SQLite write transaction serializing concurrent duplicates (D4). | `verify`: fire N concurrent identical requests, assert cert + audit counts equal a single run's counts. |
| A3. Key misuse | Alice reuses the same key with a different course/payload. | 409, no second op, first result not overwritten. | Stored request hash compared on key hit; mismatch → 409 (D4). | `verify`: reuse key with different `courseId` → 409, counts unchanged, first result intact. |
| A4. Learner outcomes | Course has completed, incomplete, and already-certified learners. | Only eligible learners get certs; incomplete and duplicates skipped with reasons. | Eligibility = `completed` AND no active cert; per-learner outcome + reason (D4/architecture). | `verify`: bulk-issue and assert outcomes are exactly `issued`/`skipped: not-completed`/`skipped: already-certified`. |
| A5. DST & local date | East cert UTC `2026-01-10T13:30:00Z`; West same instant. | East `2026-01-11 00:30` (Sydney +11); West `2026-01-10 21:30` (Perth +8). List sort and CSV use tenant-local calendar date. | UTC storage + IANA zone via `Intl`; `issued_date_local` denormalized per tenant for sort/CSV (D5). | `verify`: assert local date strings for the two known instants; assert sort/CSV use `issued_date_local`. |
| A6. Export growth | Generate 100k East certs incl. equal sort keys; search+sort; export twice; hit list during first export. | Each export ≤60s; CSV has exactly the matching rows in requested order; equal keys keep stable relative order across runs; list succeeds during export. | Keyset streaming with event-loop yields; deterministic total-order comparator ending in `id` (D5/D6). | `verify`: run export, measure duration + row count + order, compare two exports byte-for-byte, and confirm a list request completes mid-export. |
| A7. Revocation audit | Alice revokes a valid cert, then repeats. | First request flips status and writes one `revoked` audit; repeat creates no duplicate audit. | Revoke writes one audit row; repeat on already-revoked is a no-op (architecture). | `verify`: revoke, assert one audit row; repeat, assert still one. |
